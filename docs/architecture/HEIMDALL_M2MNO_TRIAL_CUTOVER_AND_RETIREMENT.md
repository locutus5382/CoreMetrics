# HEIMDALL M2-M/N/O — Combined preparation, staged activation and legacy retirement

**18 November 2026** · Based on **M2-L** commit `a442ab9266899d6477f9c32bf1741f624327b6ac`, which passed the full Android build/JVM and five API33 emulator groups in two CI runs.

## Product decision

Prepare the trial, default-engine selection policy and retirement inventory together to shorten engineering time, but do NOT perform the three irreversible actions together. No PR is authorized to select Heimdall as the default or delete the legacy service's recording loop until actual Odin 2 Portal data, rollback and regression evidence are approved.

### M2-M: Side-by-side Odin trial — **implemented in this PR**

A new **`heimdallTrial`** build type uses `applicationIdSuffix=".heimdalltrial"`, a different app name (`HEIMDALL Trial`), separate system UID/data directory, SQLite database, recovery preferences, content-provider authority and Quick Settings tile components. It is signed with the CI runner's debug certificate. It cannot overwrite the normal `com.locutus5382.coremetrics` installation. The default regular DEBUG/RELEASE/optimizedTest variants remain unchanged; `BuildConfig.HEIMDALL_TRIAL` is false in all those variants, and true only in this trial.

The trial app contains a non-exported `HeimdallTrialActivity` accessible from **Settings → Open Heimdall device test console** only when the build is a trial. The console provides guarded user-initiated **Start Heimdall test recording**, **STOP / retry finalization**, **Refresh verified status**, and **Copy diagnostic summary**. It reads service-owned status and the real SQLite row/sample count on the IO dispatcher; it never creates a second service, writer, overlay or session. An absent/unknown status disables Start. The service revalidates lease, original unfinished database row, foreground requirements and legacy owner independent of the UI.

The new CI build task `:app:testHeimdallTrialUnitTest :app:assembleHeimdallTrial` uploads `HEIMDALL-M2M-isolated-Odin-debug-trial-APK`. CI uses aapt to **assert the APK package ID** is `com.locutus5382.coremetrics.heimdalltrial`. If the assertion fails, the artifact should not be treated as safely isolated.

#### Odin test protocol (do these in order)

1. **Before installation:** back up any valuable CoreMetrics session data from the ORIGINAL app using its portable session archive. Do not uninstall CoreMetrics or clear its data. Retain the original APK for rollback. Charge the Odin and allow notifications for the trial app.
2. **Install only the artifact** named `HEIMDALL-M2M-isolated-Odin-debug-trial-APK` from a successful GitHub Actions build. Verify the launcher says **HEIMDALL Trial** and that CoreMetrics remains installed. Do not install a normal `app-debug.apk` over CoreMetrics for this trial.
3. Open HEIMDALL Trial → **Settings** → **Open Heimdall device test console**. Read its status. Start must be disabled if any unfinished trial session or active recovery lease exists; do not clear its data to make Start appear enabled.
4. Grant notification permission if asked, then run one **30–60-second recording without a game**. Refresh the console; confirm exact original session ID, lease owner `HEIMDALL_DEBUG`, `RECORDING` phase and increasing **persisted** sample count. Press **STOP**, refresh and confirm the same SQLite row is `COMPLETED` and the lease owner is cleared.
5. Run one **10-minute test** using Odin's launcher/Eden/game transition. Verify the original row, sample continuity, battery/CPU/GPU values in the trial app's session view and STOP completion. Keep the screen/overlay expectations separate: the current new engine does **not** yet provide the final three redesigned HUDs.
6. Test Quick Settings STOP only if the tile is explicitly added from the **trial** app and distinguishable from the original CM REC tile. Check that the same trial session is finalized, not a new one.
7. For controlled fault tests, capture/export the trial's diagnostics first. Process death, shutdown, low-storage or force-stop tests must be supervised; a force-stop may prevent Android auto-restart and **must not** be mistaken for a guaranteed Android lifecycle callback. Never use the original CoreMetrics app as a crash-test target.
8. Inspect and export trial session analytics and one DUKO A/B comparison, then report original session IDs, durations, sample counts, device firmware/Android version and any errors. Do not include unrelated personal data.
9. **If a trial session is not finalized:** do NOT wipe the trial app, delete SQLite, manually remove the recovery lease or install a new debug APK over it. Copy the diagnostic summary and preserve the sandbox for repair.

**Note:** Debug builds generated by separate GitHub CI runners may use different debug signing certificates. An update can fail due to signature mismatch. Do not uninstall a trial with unfinished sessions merely to install a newer APK. Test with the specific successful APK first.

### M2-N: Reversible default-engine selection — **prepared, NOT activated**

- `BuildConfig.HEIMDALL_NATIVE_DEFAULT` is false in all build types.
- `HeimdallCutoverPolicy` is a pure fail-closed contract (13 JVM tests). Eligibility requires explicit Odin validation, full CI, user approval, a backup of previous sessions, a verified rollback APK, no active legacy recorder, no legacy or unresolved Heimdall recovery lease, no unfinished SQLite recording and no attached legacy HUD.
- This PR deliberately does **not** call the new policy from release `RecordingService.onStartCommand` to change live dispatch, because the existing native host is still guarded by a debug-only ownership transfer. Production cutover needs a reviewed single-owner service dispatcher that can do native START/RECOVER in release safely.
- After Odin verification, implement and validate that one dispatcher with **Heimdall as default for new recordings and legacy solely as recovery support for an existing LEGACY lease**, plus a durable, safely reversible feature gate. A failed candidate falls back only when there is no active or unresolved native/legacy session; never switch owners mid-session.

### M2-O: Legacy engine removal — **inventory prepared, no deletion yet**

**Candidates for retirement AFTER cutover:**
- Legacy sample-loop, STOP/finalizer/retry and mutable flag branches INSIDE `monitor/RecordingService.kt`; preserve the single Android foreground-service component, notification ownership and single process.
- Obsolete `RecorderHud` / `MonitorHudOwner` lifecycle pathways **only after** the Heimdall HUD studio's renderer replaces their actual WindowManager behavior and passes duplicate-attachment/interaction/crash tests.
- Redundant legacy tile actions/status transformations after adopting one Heimdall-owned REC tile; do not prematurely remove the user's ability to stop or recover a recording.
- Legacy-only recovery fields and compatibility shims after all pre-existing LEGACY session rows/leases are terminal and export/restore works.

**Must remain as reusable infrastructure:**
- `telemetry/DirectSampler.kt`, CPU/GPU device adapters, `ForegroundAttribution`, capabilities probing and Android privacy permissions.
- `data/SessionStore.kt`, schema v9, SQLite migration and original-session identity, `SessionArchive`, exports and report dataset loaders.
- `analysis/` A/B comparison, scoring, DUKO analytics and existing report generation.
- The single `:monitor` service, private `StatusProvider` (or its compatible replacement), user-visible notification and ownership synchronization until they are replaced by tested equivalents.

**Removal gate:** one or more successful real Odin recording/STOP/restart sessions; no duplicate sampler/HUD/window; normal and interrupted session export integrity; a stable reversible default-runtime build; approved migration of UI/QS/HUD; full JVM/instrumentation/release/optimized build. Only then delete code in a follow-up PR with tests that detect any remaining legacy recorder dependencies.

## CI and release caveats

- All HEIMDALL PRs remain stacked drafts in the original `locutus5382/CoreMetrics` repository. The trial build is **not** a published release and is not the final visual/product rename.
- This branch must first pass `testHeimdallTrialUnitTest`, `assembleHeimdallTrial`, the independent package-ID verification and the existing five API33 emulator groups.
- The main installation and its SQLite v9 data are untouched by this branch. A separate test package proves isolation, but it does **not** prove migration of historical data to a future application ID. Historical in-place migration/backup must receive a later dedicated regression test before the final Play Store/repository rename.
